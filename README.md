# 킬렐러 우체국 (The Kilrelagh Post)

페이건 오멘 스쿨 세계관 참여자 전용 사이트입니다. 초대 코드를 아는 사람만 들어올 수 있습니다.

- **광장 · 장소별 채널**: 실시간 채팅 (광장, 페이건 오멘 스쿨, 킬렐러 마을, 성 카흘루 예배당, 캐슬 페이건, 늪과 숲)
- **게시판**: 글과 댓글
- **쪽지함**: 인물끼리 주고받는 1:1 쪽지 (대화 당사자 두 사람만 읽을 수 있음)
- **둘만의 방**: 장소와 상황을 정해 두 인물만 들어가는 실시간 채팅방
- **NPC**: 운영자가 정해 둔 인물들. 이름을 부르면 대답하고, 하루 두 번 게시판에 글을 올리고, 가끔 채팅에 끼어듦 (선택 기능, 8단계)
- **인물록 · 내 캐릭터**: 자작 캐릭터 프로필 (한 계정에 8명까지)

GitHub Pages(무료 호스팅)에 파일을 올리고, Firebase(구글의 무료 데이터베이스·로그인 서비스)를 연결해서 씁니다. 처음 한 번만 설정하면 됩니다. 약 20분 걸립니다.

---

## 파일 구성

```
index.html         사이트 뼈대
app.js             기능 전체
style.css          디자인
config.js          ← Firebase 연결 정보를 넣는 파일 (2단계에서 수정)
firestore.rules    ← 보안 규칙 (4단계에서 Firebase에 붙여 넣기)
fonts/             KoPub 서체 (반드시 폴더째 올리기)
audio/             채널별 배경음악 — square.mp3(광장), school.mp3(페이건 오멘 스쿨), kilrelagh.mp3(킬렐러 마을), chapel.mp3(성 카흘루 예배당), castle.mp3(캐슬 페이건), marsh.mp3(늪과 숲), default.mp3(그 밖의 화면) (반드시 폴더째 올리기)
README.md          이 안내서
npc/               NPC 설정(npcs.json)과 실행 스크립트, 비밀번호 초기화 스크립트
.github/workflows/npc.yml   NPC를 10분마다 깨우는 GitHub Actions 설정 (8단계)
.github/workflows/reset-password.yml   관리자용 비밀번호 초기화 (7단계 아래)
```

## 1단계. Firebase 프로젝트 만들기

1. https://console.firebase.google.com 에 구글 계정으로 들어갑니다.
2. **프로젝트 추가** → 이름 입력(예: `kilrelagh-post`) → Google 애널리틱스는 꺼도 됩니다 → 만들기.

## 2단계. 웹 앱 등록하고 config.js 채우기

1. 프로젝트 첫 화면에서 **웹(`</>`) 아이콘**을 누릅니다.
2. 앱 닉네임 입력(아무거나) → "Firebase 호스팅"은 체크하지 않음 → **앱 등록**.
3. 화면에 나오는 `const firebaseConfig = { ... }` 안의 값들을 복사합니다.
4. `config.js`를 메모장 등으로 열어 `YOUR_...` 자리를 방금 복사한 값으로 바꿉니다.

```js
export const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "kilrelagh-post.firebaseapp.com",
  projectId: "kilrelagh-post",
  storageBucket: "kilrelagh-post.appspot.com",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abc..."
};
```

> 이 값들은 공개돼도 괜찮은 식별자입니다. 실제 보호는 4단계의 보안 규칙이 맡습니다.

## 3단계. 로그인 켜기

1. 왼쪽 메뉴 **빌드 → Authentication** → **시작하기**.
2. **로그인 방법** 탭에서 **이메일/비밀번호** → 사용 설정 → 저장. (그 아래 '이메일 링크'는 켜지 않아도 됩니다.)

> 사이트는 **아이디·비밀번호**로만 가입합니다. 이메일은 받지 않습니다. Firebase가 이메일 형식을 요구하기 때문에 사이트가 속으로 아이디를 `아이디@users.kilrelagh.post` 형태로 바꿔서 넘길 뿐이고, 이 주소로 메일이 가지는 않습니다. 그래서 Authentication → 사용자 탭에는 참여자들이 이 형태로 보입니다.

## 4단계. 데이터베이스 만들고 보안 규칙 넣기

1. 왼쪽 메뉴 **빌드 → Firestore Database** → **데이터베이스 만들기**.
2. 위치는 **asia-northeast3 (서울)** 추천 → **프로덕션 모드**로 시작.
3. 만들어지면 **규칙** 탭으로 갑니다.
4. 안에 있는 내용을 전부 지우고, `firestore.rules` 파일 내용을 통째로 붙여 넣은 뒤 **게시**.

## 5단계. 초대 코드 정하기

1. Firestore의 **데이터** 탭 → **컬렉션 시작**.
2. 컬렉션 ID: `config`
3. 문서 ID: `invite`
4. 필드: 이름 `code`, 유형 `string`, 값은 원하는 초대 코드 (예: `stars-are-turned`)
5. 저장.

이 코드를 참여자들에게만 알려 주세요. 나중에 값을 바꾸면 **새로 가입하는 사람**에게만 적용되고, 이미 들어온 회원은 그대로 남습니다.

## 6단계. GitHub에 올리기

1. GitHub에서 새 저장소를 만듭니다 (예: `kilrelagh-post`, Public).
2. 압축을 푼 폴더 **안의 내용물 전체**를 저장소 맨 위에 올립니다.
   - **Add file → Upload files** 화면에 파일과 `fonts` 폴더를 **함께 끌어다 놓으세요.**
   - 올린 뒤 저장소에 `fonts` 폴더가 보이는지 꼭 확인하세요. 폴더 없이 서체 파일만 흩어져 올라가면 서체가 기본 서체로 바뀝니다.
3. 저장소 **Settings → Pages** → Source: **Deploy from a branch**, Branch: `main`, `/ (root)` → Save.
4. 1~2분 뒤 `https://내아이디.github.io/kilrelagh-post/` 로 접속됩니다.

## 7단계. 나를 관리자로 만들기

1. 사이트에서 아이디·비밀번호·초대 코드로 가입해 들어갑니다.
2. Firebase 콘솔 → Authentication → **사용자** 탭에서 `내아이디@users.kilrelagh.post` 줄의 **사용자 UID**(긴 영문·숫자)를 복사합니다.
3. Firestore **데이터** 탭 → `members` 컬렉션 → 방금 복사한 UID와 같은 이름의 문서를 엽니다.
4. `role` 값을 `member` → `admin` 으로 바꿉니다.

관리자는 다른 사람의 메시지·글·댓글·캐릭터를 지울 수 있고, 아래의 비밀번호 초기화 결과를 볼 수 있습니다.

## 비밀번호를 잊은 참여자가 있을 때

이메일이 없어서 '비밀번호 재설정 메일'은 보낼 수 없습니다. 대신 관리자가 GitHub에서 임시 비밀번호로 바꿔 줍니다.

1. (처음 한 번) 8단계 설정 순서 1번처럼 저장소 Secrets에 `FIREBASE_SERVICE_ACCOUNT`를 넣고, `.github/workflows/reset-password.yml` 파일을 올려 둡니다. NPC를 안 쓰더라도 이 둘은 필요합니다.
2. 저장소 **Actions** 탭 → 왼쪽 **비밀번호 초기화** → **Run workflow** → 아이디 입력 → 실행.
3. 1분쯤 뒤 사이트에서 관리자 계정으로 **내 캐릭터** 화면 맨 아래를 보면 그 아이디의 **임시 비밀번호**가 있습니다.
4. 임시 비밀번호를 본인에게 전달하고 **전달했어요 · 지우기**를 누릅니다.
5. 본인은 임시 비밀번호로 로그인한 뒤 **내 캐릭터 → 비밀번호 바꾸기**에서 새 비밀번호로 바꿉니다.

> 임시 비밀번호는 GitHub 실행 기록에 남지 않습니다. 저장소가 공개여도 다른 사람은 볼 수 없습니다.

## 8단계 (선택). NPC가 말하게 하기

NPC는 GitHub Actions(GitHub의 무료 자동 실행 기능)가 10분마다 깨웁니다. 깨어날 때마다 이렇게 합니다.

- **이름을 부르면 대답:** 채널 메시지, 게시글, 댓글에 NPC 이름(또는 `aliases`에 적은 호칭, 예: "펜 선생", "여관 아주머니")이 들어 있으면 그 NPC가 같은 곳에 대답합니다. GitHub 예약 실행은 몇 분씩 늦어질 때가 있어서 보통 10~20분 안에 대답합니다. 밤에도 대답합니다. 쪽지와 둘만의 방은 NPC가 들어갈 수 없습니다.
- **하루 두 번 게시글:** 매일 한국 시간 10~13시, 19~22시 사이의 무작위 시각에 게시판에 글을 하나씩 올립니다. `canPost`가 `true`인 NPC가 번갈아 씁니다.
- **가끔 한마디:** 정해 둔 확률로 채팅이나 댓글에 한마디 끼어듭니다. 기본값이면 하루 10번 안팎이고, 한국 시간 새벽 2~8시에는 쉽니다.

**준비물 두 가지**

1. **Claude API 키**: https://console.anthropic.com 에서 가입하고 결제 수단(크레딧)을 등록한 뒤 **API Keys**에서 새 키를 만듭니다. `sk-ant-`로 시작합니다.
   - 기본 모델(`claude-haiku-5-5`)은 가장 저렴한 모델이라, 이 정도 횟수면 비용이 아주 적게 나옵니다. 정확한 요금은 콘솔의 요금 안내를 확인하세요.
2. **Firebase 관리자 키**: Firebase 콘솔 → 톱니바퀴 **프로젝트 설정** → **서비스 계정** 탭 → **새 비공개 키 생성** → JSON 파일이 내려받아집니다.
   - 이 파일은 데이터베이스 전체를 다룰 수 있는 열쇠입니다. **절대 저장소에 파일로 올리지 말고**, 아래처럼 Secrets에만 넣으세요.

**설정 순서**

1. 저장소 **Settings → Secrets and variables → Actions → New repository secret**에서 두 개를 만듭니다.
   - 이름 `ANTHROPIC_API_KEY`, 값: Claude API 키
   - 이름 `FIREBASE_SERVICE_ACCOUNT`, 값: 내려받은 JSON 파일을 메모장으로 열어 **내용 전체**를 복사해 붙여 넣기
2. `.github/workflows/npc.yml` 파일이 저장소에 올라가 있는지 확인합니다.
   - 이름이 점(.)으로 시작하는 폴더는 컴퓨터에서 숨김 폴더라 끌어다 놓을 때 빠지기 쉽습니다. 저장소에 `.github` 폴더가 안 보이면 **Add file → Create new file**을 누르고, 파일 이름 칸에 `.github/workflows/npc.yml`을 그대로 입력한 뒤 압축 파일 속 `npc.yml` 내용을 붙여 넣어 저장하세요.
3. 저장소 **Actions** 탭 → (처음이면 활성화 버튼) → 왼쪽 **NPC** → **Run workflow**를 누르면 확률과 상관없이 바로 한 번 말합니다. 1분쯤 뒤 사이트 광장이나 게시판을 확인해 보세요.
   - 실패하면 실행 기록을 눌러 빨간 단계의 메시지를 확인하세요. 보통 Secrets 값을 잘못 붙여 넣은 경우입니다.

**NPC 바꾸기** — `npc/npcs.json`을 고치면 됩니다.

- `npcs`: 인물 목록. `name`(이름), `bio`(소개), `voice`(말투와 성격), `channels`(말할 채널 id: `square`, `school`, `kilrelagh`, `chapel`, `castle`, `marsh`), `canPost`(게시글을 쓸지)
- `chance`: 10분마다 스스로 한마디 할 확률 (0.12 = 12%). 더 자주 말하게 하려면 숫자를 올리세요.
- `postsPerDay`, `postWindowsKST`: 하루 게시글 수와 시간대 (한국 시간 `[시작, 끝]`). 시간대를 하나 더 적고 숫자를 3으로 바꾸면 하루 세 번 올립니다.
- `aliases`(인물마다): 이름 말고도 이 NPC를 부르는 호칭. 너무 흔한 단어(예: "펜")는 엉뚱한 말에도 대답하니 피하세요.
- `replyToMentions`, `maxRepliesPerRun`: 이름을 부르면 대답할지, 한 번 깨어날 때 최대 몇 번 대답할지
- `quietHoursKST`: 말하지 않는 시간 (한국 시간 기준 `[시작, 끝]`)
- `weights`: 스스로 한마디 할 때 채팅과 댓글을 고르는 비율
- `world`, `secrets`: NPC가 알고 있는 세계관과, 직접 말하지 말고 암시만 할 비밀
- `model`: 쓸 Claude 모델
- `topics`(인물마다), `commonTopics`: NPC가 새 말을 꺼낼 때 돌아가며 고르는 화제 목록. 최근에 고른 화제는 한동안 다시 고르지 않습니다.
- `noRepeat`: 반복 막기 설정. NPC들이 최근에 한 말 `historySize`개(기본 30)를 기억해 두고, 새 대사가 그중 하나와 `similarity`(기본 0.45, 0~1) 이상 비슷하면 버리고 다시 씁니다(`retries`번까지). 같은 NPC가 두 번 연속 차례를 잡지 않고, 한 채널에서 같은 NPC가 연달아 말하지도 않습니다.

NPC는 인물록에 `NPC` 표시와 함께 나타나며, 쪽지나 둘만의 방 상대로는 고를 수 없습니다. 인물 이름을 바꾸면 다음 실행 때 인물록에도 반영됩니다.

> GitHub는 저장소에 60일 동안 아무 변경이 없으면 예약 실행을 자동으로 멈춥니다. NPC가 조용해졌다면 Actions 탭에서 다시 켜 주세요.

## 사용법

- **가입**: `가입하기`에서 아이디(영문 소문자·숫자·밑줄 3~20자), 비밀번호(6자 이상), 초대 코드를 넣으면 바로 들어갑니다. 아이디는 나중에 바꿀 수 없고, 비밀번호는 `내 캐릭터 → 비밀번호 바꾸기`에서 바꿀 수 있습니다.
- **처음 들어오면** `내 캐릭터 → 새 캐릭터`에서 인물을 만듭니다. 대화와 글은 모두 캐릭터 이름으로 남습니다.
- **말하는 인물 바꾸기**: 위쪽 메뉴 오른쪽의 `말하는 인물` 선택 칸.
- **채팅**: Enter 보내기, Shift+Enter 줄바꿈. `/me 문을 연다` 또는 `*문을 연다*`처럼 쓰면 `— 이름 문을 연다` 형태의 행동 묘사로 표시됩니다.
- **쪽지**: 인물록에서 상대 인물을 열고 `쪽지 보내기`. 같은 두 인물 사이의 쪽지는 한 대화로 모입니다.
- **둘만의 방**: 인물록에서 상대 인물을 열고 `둘만의 방 열기` → 장소와 상황 메모를 정하면 두 사람만 들어가는 채팅방이 생깁니다. 같은 상대와도 장면마다 방을 여러 개 열 수 있고, 장면이 끝나면 `방 닫기`로 기록만 남길 수 있습니다.
- **프로필 그림**: 올리면 자동으로 정사각형으로 잘리고, `도트로 바꾸기`를 켜 두면 흑백 점묘 그림이 됩니다.

## 운영 메모

- **회원 내보내기**: Firestore `members` 컬렉션에서 그 사람의 문서를 지우면 더 이상 아무것도 볼 수 없습니다. (다시 들어오려면 초대 코드가 필요합니다. 초대 코드도 함께 바꾸세요.)
- **채널 바꾸기**: `app.js` 맨 위의 `CHANNELS` 목록에서 이름과 설명을 고치거나 줄을 추가하면 됩니다. `id`는 영문 소문자로 쓰고, 이미 대화가 쌓인 채널의 `id`는 바꾸지 마세요.
- **소속 목록 바꾸기**: 같은 위치의 `AFFILIATIONS` 목록을 고치면 됩니다.
- **무료 한도**: Firebase 무료 요금제(Spark)는 하루 읽기 5만 건, 쓰기 2만 건 정도까지 무료입니다. 수십 명 규모 커뮤니티라면 보통 넉넉합니다. 한도를 넘으면 그날은 잠시 멈추고 다음 날 풀리며, 카드를 등록하지 않는 한 요금이 나가지 않습니다.
- **쪽지 공개 범위**: 사이트 안에서는 대화 당사자 두 사람만 쪽지를 볼 수 있습니다. 다만 Firebase 콘솔에 들어갈 수 있는 운영자는 데이터베이스를 직접 열어 볼 수 있으니, 참여자들에게 이 점을 알려 두는 것이 좋습니다.
- **채널별 배경음악**: 광장은 `audio/square.mp3`, 페이건 오멘 스쿨 채널은 `audio/school.mp3`, 킬렐러 마을 채널은 `audio/kilrelagh.mp3`, 성 카흘루 예배당 채널은 `audio/chapel.mp3`, 캐슬 페이건 채널은 `audio/castle.mp3`, 늪과 숲 채널은 `audio/marsh.mp3`가 나오고, 게시판·쪽지함·둘만의 방·인물록·내 캐릭터 화면에서는 `audio/default.mp3`가 나옵니다 (이 화면들끼리 옮겨 다닐 때는 곡이 끊기지 않고 이어집니다). 같은 이름의 다른 곡으로 바꾸면 교체됩니다. 채널을 새로 만들어 음악을 넣으려면 `app.js`의 `CHANNEL_MUSIC` 목록에 `채널id: "audio/파일이름.mp3"` 한 줄을 추가하고 파일을 올리세요. 오른쪽 아래 버튼으로 끌 수 있고, 끈 상태는 기억됩니다.
